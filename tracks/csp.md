# HCPN Indonesia — CSP Track

> **Track Focus:** Solution Integration, Cloud-Native Architecture, AI & Data, Pre-Sales, Solution Packaging, Demo/PoC, and Go-to-Market  
> **6-Month Outcome:** **Solution Ready**  
> **12-Month Outcome:** **Specialized, Customer-Validated, Go-to-Market Ready CSP**

---

## 1. Track Purpose

The CSP Track is designed to develop Cloud Solution Provider capability beyond basic resale.

A CSP should be able to combine Huawei Cloud services with its own services, managed services, applications, or third-party solutions into a packaged customer offering.

The intended progression is:

**Cloud Foundation → Solution Architecture → AI/Data Capability → Cloud-Native Integration → Pre-Sales Readiness → Packaged Solution → Demo/PoC → GTM**

This track should produce a real, demonstrable solution capability rather than only training completion.

---

Recommended participants:

- Technical Consultant
- Product Manager

- Cloud Engineer

- Managed Service Lead

| Role | Recommended Participation |
|---|---|

---

## 3. Entry Requirements

Recommended minimum readiness:

- basic cloud-computing knowledge;
- familiarity with application and infrastructure architecture;
- understanding of customer requirements and solution design;
- basic knowledge of networking and security;
- experience with pre-sales, productization, or implementation is preferred.

Optional baseline assessment:

- cloud fundamentals;
- architecture fundamentals;
- pre-sales maturity;
- current solution portfolio;
- integration capability;
- cloud-native maturity.

---

## 4. 6-Month Capability Objective

By the end of Month 6, a CSP should be able to:

1. explain Huawei Cloud core and cloud-native services;
2. design a high-level integrated cloud solution;
3. identify relevant AI and Data use cases;
4. integrate Huawei Cloud services with partner-owned or third-party components;
5. translate customer requirements into a solution architecture;
6. prepare a pre-sales solution proposal;
7. define a solution Bill of Materials at a high level;
8. demonstrate or prototype the solution;
9. package the solution as a repeatable offering;
10. present the solution commercially and technically;
11. define an initial GTM plan;
12. pass the CSP Solution Readiness Assessment.

# 5. Month 1 — HCCDA Cloud Native Foundation

## Theme

**Foundation**

## Objective

Build a common technical foundation for cloud-native solution development and integration on Huawei Cloud.

## Core Topics

- Huawei Cloud overview
- Cloud-native concepts
- Compute
- Storage
- Networking
- IAM and security fundamentals
- Container fundamentals
- Kubernetes overview
- Microservices concepts
- API-based integration
- Observability basics
- DevOps overview
- Managed cloud services overview

## Learning Outcomes

Participants should be able to:

- explain cloud-native architecture at a high level;
- identify Huawei Cloud components used in modern application platforms;
- explain basic container and Kubernetes concepts;
- identify integration points between Huawei Cloud and partner solutions.

## Recommended Delivery

| Activity | Duration |
|---|---:|
| Instructor-Led Training | 4 hours |
| Technical Demo | 2 hours |
| Hands-on / Self Learning | 3 hours |
| Assessment | 30 minutes |

## Practical Assignment

Create a simple reference architecture containing:

- application tier;
- compute/container layer;
- networking;
- storage/database;
- IAM/security;
- monitoring.

## Capability Gate

- [ ] foundation training completed;
- [ ] reference architecture submitted;
- [ ] technical assessment completed;
- [ ] architecture reviewed by track owner.

# 6. Month 2 — Solution Architecture & Integration

## Theme

**Architecture**

## Objective

Develop the ability to convert customer requirements into an integrated Huawei Cloud solution architecture.

## Core Topics

- Requirement discovery
- Functional requirements
- Non-functional requirements
- Availability
- Scalability
- Security architecture
- Network architecture
- Data architecture
- Integration patterns
- API integration
- Hybrid integration
- High availability
- Backup and DR
- Observability
- Architecture trade-offs
- Cost-aware design

## Suggested Architecture Framework

Use:

**Business → Application → Data → Integration → Infrastructure → Security → Operations → Cost**

## Learning Outcomes

Participants should be able to:

- capture technical requirements;
- design a high-level solution architecture;
- identify integration dependencies;
- explain architecture decisions;
- document risks and assumptions.

## Practical Assignment

Design an integrated solution for a customer scenario.

Minimum deliverables:

- high-level architecture;
- component mapping;
- integration points;
- security considerations;
- assumptions;
- risks;
- expected business benefits.

## Capability Gate

- [ ] architecture submitted;
- [ ] integration points identified;
- [ ] architecture review completed;
- [ ] major risks and assumptions documented.

# 10. Month 6 — CSP Solution Design & Readiness Assessment

## Theme

**Validation**

## Objective

Validate that the CSP can design, package, demonstrate, and position an integrated Huawei Cloud solution.

## Capstone Requirement

Each CSP should produce at least **one packaged solution**.

Examples:

- Huawei Cloud + Managed Services
- Huawei Cloud + Cybersecurity Solution
- Huawei Cloud + AI Solution
- Huawei Cloud + SaaS Application
- Huawei Cloud + Data Platform
- Huawei Cloud + Backup / DR Service
- Huawei Cloud + Cloud-Native Application Platform

## Minimum Capstone Deliverables

1. solution name;
2. target customer segment;
3. problem statement;
4. value proposition;
5. high-level architecture;
6. Huawei Cloud components;
7. partner / third-party components;
8. integration design;
9. security considerations;
10. Bill of Materials;
11. pricing/commercial logic at an appropriate level;
12. demo or PoC plan;
13. sales pitch;
14. go-to-market plan.

## Assessment Components

| Assessment | Weight |
|---|---:|
| Architecture Quality | 20% |
| Integration Capability | 20% |
| Technical Feasibility | 15% |
| Business Value | 15% |
| Pre-Sales Proposal | 10% |
| Demo / PoC Readiness | 10% |
| GTM Readiness | 10% |
| **Total** | **100%** |

## Suggested Readiness Levels

| Score | Status |
|---|---|
| < 50 | Foundation |
| 50–69 | Developing |
| 70–84 | Solution Ready |
| 85–100 | Advanced Solution Ready |

> These thresholds are proposed program-management values and are not official Huawei Cloud or HCPN qualification thresholds.

## Month 6 Exit Criteria

A CSP becomes **Solution Ready** when:

- [ ] mandatory modules completed;
- [ ] architecture assignments completed;
- [ ] AI/Data use case completed;
- [ ] integration demo completed;
- [ ] pre-sales proposal completed;
- [ ] packaged solution submitted;
- [ ] final assessment passed;
- [ ] initial GTM plan completed.

# 11. Monthly Delivery Model

Each month follows:

## Week 1 — Learn

Instructor-led or online learning.

## Week 2 — Practice

Architecture workshop, lab, or technical demo.

## Week 3 — Apply

Solution assignment, prototype, proposal, or packaged-solution development.

## Week 4 — Validate

Architecture review, demo review, assessment, or readiness validation.

Operating model:

**Learn → Practice → Apply → Validate**

# 20. Definition of Success

The CSP Track should not be reported only as:

> "20 engineers completed CSP training."

A stronger management report is:

```text
20 participants trained
        ↓
18 completed
        ↓
15 architecture-ready
        ↓
12 integration-ready
        ↓
8 packaged solutions
        ↓
6 customer demos
        ↓
4 PoCs
        ↓
2 production deployments
        ↓
business outcome
```

This creates a measurable relationship between enablement and solution commercialization.
