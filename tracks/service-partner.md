# HCPN Indonesia — Service Partner Track

> **Track Focus:** Technical Delivery, Architecture, Migration, Cloud Native, Operations & Maintenance, and Professional Services  
> **6-Month Outcome:** **Technical Delivery Ready**  
> **12-Month Outcome:** **Advanced, Industry-Aware, Production-Ready Service Partner**

---

## 1. Track Purpose

The Service Partner Track is designed to build practical technical capability for partners responsible for implementation, migration, operations, maintenance, managed services, and professional services on Huawei Cloud.

The intended progression is:

**Technical Foundation → Architecture → Migration → Cloud Native & Data → Advanced Certification Readiness → End-to-End Service Delivery**

This track is deliberately hands-on. Completion should demonstrate that the partner can design, deploy, migrate, operate, and support customer workloads—not only attend training.

## 3. Entry Requirements

Recommended minimum readiness:

- basic cloud computing knowledge;
- fundamental Linux and/or Windows administration;
- basic TCP/IP networking knowledge;
- familiarity with virtualization;
- understanding of compute, storage, and database concepts;
- ability to use command-line interfaces is recommended;
- access to approved Huawei Cloud lab or sandbox environment where applicable.

Suggested pre-assessment:

- cloud fundamentals quiz;
- networking fundamentals;
- virtualization fundamentals;
- Linux / Windows administration baseline;
- architecture maturity survey;
- migration experience survey.

---

## 4. 6-Month Capability Objective

By the end of Month 6, a Service Partner should be able to:

1. deploy core Huawei Cloud infrastructure components;
2. design a basic highly available cloud architecture;
3. understand networking, IAM, security, monitoring, backup, and DR fundamentals;
4. assess an existing customer workload for migration;
5. create a basic migration plan;
6. deploy or modernize workloads using cloud-native patterns where appropriate;
7. understand operational monitoring and service management requirements;
8. produce implementation and operational documentation;
9. complete an end-to-end technical delivery scenario;
10. pass the Service Partner Technical Delivery Readiness Assessment.

# 5. Six-Month Learning Roadmap

## Month 1 — Huawei Cloud Technical Foundation

### Theme

**Foundation**

### Objective

Build hands-on understanding of Huawei Cloud core infrastructure and operational services.

### Core Topics

- Huawei Cloud technical overview
- Regions and Availability Zones
- Elastic Cloud Server / compute concepts
- VPC
- Subnets
- Security Groups
- Elastic IP
- Load balancing fundamentals
- Block and object storage concepts
- Cloud database overview
- IAM fundamentals
- Monitoring and logging basics
- Backup fundamentals
- Security fundamentals
- Resource tagging and organization

### Learning Outcomes

Participants should be able to:

- navigate the Huawei Cloud environment;
- provision core infrastructure resources;
- build a basic VPC topology;
- apply basic access controls;
- deploy a simple compute workload;
- understand storage options;
- configure baseline monitoring and backup concepts.

### Recommended Delivery

| Activity | Duration |
|---|---:|
| Instructor-Led Technical Session | 4 hours |
| Hands-on Lab | 4 hours |
| Self Learning | 2 hours |
| Assessment | 1 hour |

### Practical Assignment

Deploy a simple application environment containing:

- one VPC;
- public and/or private subnet design;
- compute instance;
- security group;
- storage;
- monitoring configuration;
- backup recommendation.

### Evidence

Partner may submit:

- architecture diagram;
- public-safe lab summary;
- deployment checklist;
- assessment result.

### Completion Gate

- [ ] technical foundation training completed;
- [ ] hands-on lab completed;
- [ ] basic deployment documented;
- [ ] assessment completed;
- [ ] architecture reviewed.

# 6. Month 2 — Cloud Solution Architecture

### Theme

**Architecture Capability**

### Objective

Develop the ability to design secure, scalable, available, and manageable cloud solutions.

### Core Topics

- Architecture principles
- Availability and fault tolerance
- Scalability
- High availability
- Network architecture
- Security architecture
- IAM design
- Load balancing
- Database architecture
- Backup and Disaster Recovery
- Monitoring and observability
- Capacity planning
- Cost-awareness in architecture
- Architecture documentation
- Non-functional requirements

### Learning Outcomes

Participants should be able to:

- translate business and technical requirements into architecture;
- identify single points of failure;
- design basic HA patterns;
- define security boundaries;
- select appropriate infrastructure components;
- create high-level and logical architecture diagrams.

### Recommended Delivery

| Activity | Duration |
|---|---:|
| Architecture Class | 4 hours |
| Design Workshop | 4 hours |
| Self Learning | 2 hours |
| Architecture Review | 1 hour |

### Practical Assignment

Design a highly available three-tier application architecture.

Minimum deliverables:

1. high-level architecture;
2. VPC and subnet design;
3. application tier;
4. database tier;
5. load balancing;
6. security controls;
7. monitoring approach;
8. backup / DR recommendation.

### Capability Gate

- [ ] architecture assignment completed;
- [ ] HA requirements addressed;
- [ ] security considerations documented;
- [ ] design review passed.

# 7. Month 3 — Migration & Infrastructure Modernization

### Theme

**Migration Capability**

### Objective

Enable partners to assess, plan, and execute infrastructure or application migration to Huawei Cloud.

### Core Topics

- Migration lifecycle
- Discovery and assessment
- Application dependency mapping
- Source environment analysis
- Compute migration concepts
- Database migration concepts
- Storage migration concepts
- Network preparation
- Security readiness
- Migration wave planning
- Cutover planning
- Rollback planning
- Data validation
- Downtime planning
- Backup and DR during migration
- Post-migration validation

### Suggested Migration Lifecycle

**Discover → Assess → Design → Pilot → Migrate → Validate → Optimize**

### Learning Outcomes

Participants should be able to:

- identify migration candidates;
- classify workloads;
- assess dependencies;
- define migration waves;
- identify technical risks;
- create cutover and rollback plans;
- validate post-migration outcomes.

### Practical Assignment

Prepare a migration plan for a sample on-premises three-tier workload.

Minimum deliverables:

- source environment inventory;
- dependency summary;
- target architecture;
- migration approach;
- migration waves;
- downtime assumptions;
- rollback plan;
- validation checklist;
- risk register.

### Capability Gate

- [ ] migration assessment completed;
- [ ] target architecture defined;
- [ ] migration plan submitted;
- [ ] technical risks documented;
- [ ] migration review passed.

# 8. Month 4 — Big Data, Cloud Native & DevOps

### Theme

**Modernization Capability**

### Objective

Develop basic modernization capability beyond traditional infrastructure migration.

### Core Topics

- Cloud-native concepts
- Containers
- Kubernetes fundamentals
- Microservices concepts
- CI/CD fundamentals
- Infrastructure as Code concepts
- DevOps workflow
- Logging and observability
- Application modernization patterns
- Managed services overview
- Data platform concepts
- Big Data fundamentals
- Modern application security

### Learning Outcomes

Participants should be able to:

- explain when cloud-native approaches are appropriate;
- understand containerized workloads;
- understand Kubernetes architecture at a high level;
- identify opportunities for application modernization;
- design a basic CI/CD and observability flow;
- distinguish rehost from modernization scenarios.

### Recommended Delivery

| Activity | Duration |
|---|---:|
| Technical Class | 4 hours |
| Cloud Native Lab | 4 hours |
| DevOps / Data Workshop | 3 hours |
| Assessment | 1 hour |

### Practical Assignment

Choose one:

**Option A — Cloud Native**

Containerize or model a sample application and design its deployment flow.

**Option B — DevOps**

Design a CI/CD workflow from source repository to deployment.

**Option C — Data**

Design a basic data ingestion, storage, processing, and analytics flow.

### Capability Gate

- [ ] modernization module completed;
- [ ] hands-on or design assignment completed;
- [ ] architecture reviewed;
- [ ] observability/security considerations included.

# 10. Month 6 — Service Delivery Readiness Assessment

### Theme

**Validation**

### Objective

Validate that the partner can deliver an end-to-end Huawei Cloud implementation scenario.

### Recommended Capstone Scenario

> Migrate and modernize a sample three-tier enterprise application from an on-premises environment to Huawei Cloud.

The partner must address:

1. discovery and assessment;
2. target architecture;
3. networking;
4. security;
5. compute;
6. storage;
7. database;
8. migration approach;
9. monitoring;
10. backup and DR;
11. operations;
12. documentation;
13. cutover;
14. validation;
15. handover.

### Required Deliverables

- Executive technical summary
- Current-state assessment
- Target architecture diagram
- Network design
- Security design
- Migration plan
- Implementation plan
- Monitoring design
- Backup / DR plan
- Test and validation checklist
- Rollback plan
- Operational runbook
- Handover checklist

### Suggested Assessment Components

| Assessment Area | Weight |
|---|---:|
| Technical Foundation | 10% |
| Architecture | 20% |
| Migration Planning | 20% |
| Security & Networking | 15% |
| Cloud Native / Modernization | 10% |
| Operations & Monitoring | 10% |
| Documentation | 5% |
| Technical Presentation / Defense | 10% |
| **Total** | **100%** |

### Suggested Readiness Levels

| Score | Status |
|---|---|
| < 50 | Foundation |
| 50–69 | Developing |
| 70–84 | Technical Delivery Ready |
| 85–100 | Advanced Technical Ready |

> These thresholds are proposed program-management values and are not official Huawei Cloud certification or HCPN qualification thresholds.

### Month 6 Exit Criteria

A Service Partner becomes **Technical Delivery Ready** when:

- [ ] mandatory modules completed;
- [ ] Month 1–5 assignments completed;
- [ ] capstone completed;
- [ ] architecture review passed;
- [ ] migration plan validated;
- [ ] operations documentation submitted;
- [ ] final technical presentation completed;
- [ ] readiness score meets the program target.

# 11. Recommended Learning Mix

For Service Partner training, use a higher hands-on ratio than other partner tracks:

- **30% Theory**
- **60% Hands-on / Workshop / Capstone**
- **10% Assessment**

The intended operating model is:

**Learn → Build → Test → Document → Validate**

# 21. Definition of Success

The Service Partner Track should not be reported only as:

> "40 engineers attended technical training."

A stronger management report is:

```text
40 engineers trained
        ↓
36 completed hands-on labs
        ↓
30 passed technical assessment
        ↓
24 technical-delivery-ready personnel
        ↓
12 migration / architecture assessments
        ↓
8 PoCs
        ↓
5 production deployments
        ↓
customer adoption / business outcome
```

This connects technical training to implementation capability and production workload adoption.
